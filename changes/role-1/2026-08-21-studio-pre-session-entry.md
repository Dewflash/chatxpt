# Connect Twitch directly to the authoritative Studio session

- **Type:** Fixed
- **Role:** Role 1
- **Issue/PR:** pending
- **Summary:** A clean local downloaded-app walkthrough begins with an explicitly labelled browser-local preview account, then opens normal Studio pages before Twitch authorization. Connect Twitch is an active OAuth action, validates the broadcaster server-side, imports current game and live status, creates or resumes the authoritative channel session, issues HttpOnly Studio and returning-browser grants, and never asks the streamer for a channel ID, game ID, setup key, or separate Start Session action. A configured Twitch app/chat connection remains ready when optional Extension credentials are absent, and the Game Capture recovery action opens the real capture setup instead of rendering disabled text.
- **Integration impact:** Twitch `stream.online` and `stream.offline` events start and end the mapped ChatXPT session automatically; `channel.chat.message` events continue into the private voting and privacy-safe engagement pipeline. Localhost uses user-authorized EventSub WebSockets, refreshes rotated tokens, restores delivery after app restart, and encrypts authorization in gitignored owner-only storage. Hosted HTTPS keeps signed webhooks. Missing Extension credentials disable the Extension capability while preserving hosted-board and Twitch-chat fallbacks. `npm run dev` generates stable local signing values and defaults AI to the credential-free algorithmic path without overwriting existing configuration. The manual bootstrap stays server-only and diagnostic-only. The parallel OBS slice derives normal Studio capture/overlay grants from the existing Studio/Twitch server signer when dedicated diagnostic keys are absent; its manual diagnostic endpoints still require their own keys. Saved camera permission may reconnect Gameplay Capture across later Studio session IDs.
