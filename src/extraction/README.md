# Extraction public entrypoint

Role 2 owns real-frame and audience extraction behind the canonical types exported by `index.ts`. Capabilities, provenance, confidence, freshness, and `unknown` remain explicit at this boundary.

`GameplayExtractionPipeline` adapts Role 1's ephemeral `FrameSource` into canonical gameplay snapshots. `AudienceExtractionPipeline` adapts normalised `AudienceEventSource` events into canonical audience snapshots. Implementations, sampling, OCR, calibration, and aggregation remain private to Role 2.

`createAudienceSignalPipeline` provides the first credential-free audience implementation on main. It consumes normalised audience events, keeps only privacy-safe rolling-window categories, and emits audience energy, intent, repeated-request, chat-vote, and negative-pressure signals. It does not retain raw chat text or claim real Twitch evidence from fixtures.

The current R2-P03/P03A boundary includes observation fusion, snapshot builders, bounded browser-canvas pixel sampling, a game-neutral frame-difference measurement stream, selective-region OCR experiment plumbing, and an evidence-report builder. The measurement stream consumes the canonical `FrameSource`, copies only a capped downsample, and releases every ephemeral frame before yielding. The evidence builder aggregates privacy-safe measurements against separately supplied human annotations and reports missing real-input coverage without persisting raw frames.

## Multi-game vision spine

`MultiGameVisionAnalyzer` and `streamMultiGameVisionAssessments` add a bounded multi-game layer over the same canonical `FrameSource`. The stream bridge releases every upstream frame before yielding, retains at most one 16,384-pixel downsample plus numeric motion history, and skips baseline frames before copying pixels when a faster source is available. `buildMultiGameGameplaySnapshot` projects the private assessment into the existing canonical `GameplaySnapshot`; it rejects mismatched frame/assessment timestamps and never adds Minecraft signals to generic-game snapshots.

Universal analysis is deliberately game-neutral: spatial change, global translation, residual local motion, stability, coherent or erratic whole-frame motion, mixed local activity, and broad scene changes. Pixel movement alone is never named as a camera rotation, player emotion, combat action, or other game-specific cause. The same universal frame sequence is regression-tested across generic and game-selected profiles.

Game profiles are isolated and capability-gated. A calibrated profile requires a trusted streamer configuration or platform category at confidence 0.8 or higher; visual inference alone receives the generic profile. Profile or dimension changes clear temporal state. `calibratedSignalCandidates` describe what a profile may attempt, while `supportedSignals` contains only facts confirmed by the current runtime assessment.

The initial registry contains generic action-game, Brawl Stars, and Minecraft Java vanilla profiles. The Brawl adapter requires blue-score, red-score, and centre-timer anchors across at least two recent frames before it confirms only `brawl-hud-layout` and `match-active`; timer digits, scores, and outcomes remain unknown until selective OCR/parser confirmation. Modded or unrecognised Minecraft HUDs retain universal signals but withhold calibrated facts. The Minecraft fingerprint likewise requires multiple repeating HUD anchors and currently confirms only the vanilla-like layout capability—not health or hunger values. Switching between universal and calibrated analysis clears temporal motion history.

Universal scene analysis now measures both luminance and colour change, including a bounded 64-bin colour-histogram distance. A transition still requires a near-global discontinuity followed by a stable new visual state, so colour-preserving cuts are no longer invisible without promoting ordinary effects to transitions.

Adaptive analysis defaults to 500 ms at baseline and a bounded 100 ms burst after motion spikes, ambiguous motion, or broad scene changes. The analyser returns cadence decisions without owning capture; a caller can configure Role 1's existing `BrowserMediaFrameSource` at burst-capable cadence or treat the decision as best-effort frame skipping.

`assessExtractionEvidenceAsset` classifies Role 2 gameplay/chat assets before they are used as evidence. It lets team-owned recordings and sanitised chat support real extraction evaluation, keeps synthetic fixtures fixture-only, and only permits live demo claims for privacy-reviewed OBS Virtual Camera input with separated annotations.

D2-07 through D2-11 select two-frame-per-second universal measurement, annotated-sample threshold derivation, confidence 0.75, conflict delta 0.10, three-second expiry, bounded three-frame OCR bursts, local named-crop preprocessing, and two-of-three OCR confirmation. `createBrowserTesseractOcr` now supplies a reusable worker behind the existing injected crop-only adapter, with timer/outcome character policies and explicit termination. Its worker/language/CSP behaviour remains unverified in the target browser, so it is not yet live OCR evidence.

Tests use explicitly synthetic pixel arrays, diagnostic-shaped evidence records, and injected provider/OCR transports. Multi-game tests cover trusted identity, profile isolation, cause-neutral motion, colour-preserving scene cuts, arbitrary-detail HUD false positives, Brawl and Minecraft capability gating, cadence, capture loss, release guarantees, replay summaries, and retained-sample limits. Two authorised Brawl recordings were also decoded locally through the production analyzer as diagnostic input; they were not delivered through OBS and do not establish live or OCR accuracy. No calibrated health/hunger/timer/score/outcome value or real browser/OBS run is claimed. `assessExtractionEvidenceBundle` still refuses to mark diagnostic inputs as real evidence.
